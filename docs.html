Sandbox / publishing control

Caddy API

Create, view, and delete application routes under *.{{.DomainSuffix}}.

Base URL: {{.PublicURL}}

Access

API requests require the Authorization: Bearer <token> header. Caddy also restricts access by source IP. This page can be opened without a token.

Authorization: Bearer <token>
Content-Type: application/json

Endpoints

MethodPathAction and response
GET/This documentation. HTML, 200; no token required.
PUT/apps/{name}Create or update a route. JSON with a port field. Creation returns 201; updates return 200.
GET/apps/{name}Application name, port, and URL. Returns 200; an unknown name returns 404.
GET/appsArray of applications sorted by name. Returns 200; an empty list is [].
DELETE/apps/{name}Delete a route. Returns 204 with no body; repeated deletion also returns 204.
GET/healthzAPI status: 200 with {"status":"ok"}, or 503 if configuration recovery is required. Requires a token.

Name and port

  • name: 1–63 characters using lowercase ASCII letters, digits, and hyphens. Leading or trailing hyphens, dots, and wildcards are not allowed.
  • port: an integer from {{.MinPort}} to {{.MaxPort}}, inclusive. A port assigned to another registered application cannot be used.
  • The domain is generated as {name}.{{.DomainSuffix}}. The destination IP is fixed in the API settings: {{.UpstreamIP}}.
  • The PUT body contains only port. Arbitrary domains, IP addresses, Caddy directives, and additional fields are not accepted.

Publish an application

Set the TOKEN variable to your token and choose an available port. The API does not launch the application or check its availability before publishing.

curl --fail-with-body -X PUT \
  {{.PublicURL}}/apps/my-app \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"port":{{.MinPort}}}'

A successful creation returns 201 Created:

{
  "name": "my-app",
  "port": {{.MinPort}},
  "url": "https://my-app.{{.DomainSuffix}}"
}

Repeating a PUT with the same name and port returns 200 without another reload. A PUT with a new available port updates the existing route.

List and delete

curl --fail-with-body {{.PublicURL}}/apps \
  -H "Authorization: Bearer $TOKEN"

curl --fail-with-body -X DELETE \
  {{.PublicURL}}/apps/my-app \
  -H "Authorization: Bearer $TOKEN"

Deletion removes the route from Caddy. The application keeps running; stop it before reusing its port.

Errors

StatusReason
400Invalid name, port, JSON, or additional fields.
401The token is missing or invalid.
403Caddy rejected the request based on its IP or path; the response may be plain text.
404The application or path was not found.
405The HTTP method is not supported for this path.
409The port is already assigned to another application.
503The configuration update failed or recovery is required. See the server logs for details.

API handler errors use this format:

{"error":"port already assigned to another app"}

Applying changes

The API serializes updates to the separate sandbox.caddy file, validates the entire Caddy configuration, and performs a reload. A successful response confirms that the reload has completed. On failure, the API attempts to restore the previous configuration; an incomplete rollback blocks further changes.

Docker sandbox ports must be published in advance. Applications inside the sandbox listen on 0.0.0.0:<port>. After a client timeout, check the result with GET: the operation may still complete on the server.

This documentation is embedded in the binary. The port range and IP address reflect the current server settings.
